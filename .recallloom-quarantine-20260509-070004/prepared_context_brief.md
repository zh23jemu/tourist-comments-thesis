<!-- section: mission -->
# 项目使命

- 围绕本科毕业论文《大数据背景下旅游评论挖掘及景区推荐研究——以去哪儿为例》完成论文撰写、排版完善、图表补充与系统演示支撑材料整理。
- 基于工作区内的旅游评论数据集、Flask 项目、MySQL 数据库脚本与学校论文模板，形成可提交的论文成果与可运行的演示系统。

<!-- section: audience_stakeholders -->
# 受众与相关方

- 直接使用者是当前论文作者本人。
- 关键相关方包括指导教师、学院论文审核人员以及需要查看系统演示效果的评审或答辩老师。

<!-- section: current_phase -->
# 当前阶段

- 项目处于毕业论文定稿收尾阶段。
- 论文主体内容、正式排版稿、图表补充和致谢文本已基本完成；系统运行链路已打通，当前更偏向查漏补缺与最终提交准备。

<!-- section: scope -->
# 范围

- 论文方向：旅游评论挖掘、情感分析、景区推荐、系统原型展示。
- 论文交付物：Markdown 初稿、正式排版 Word 文档、图表补充、致谢文本。
- 系统交付物：`r0703` Flask 演示系统、本地 `.venv`、Docker MySQL 运行环境、导入后的 `r0703` 数据库。

<!-- section: source_of_truth -->
# 事实来源

- 论文正文与排版相关文件以项目根目录下的 Word 与 Markdown 文件为准，重点包括 `本科毕业论文-正式排版稿.docx`、`本科毕业论文-正式排版稿_改写.docx`、`本科毕业论文初稿-大数据背景下旅游评论挖掘及景区推荐研究.md`。
- 系统实现相关事实以 `r0703` 目录下代码、SQL、数据集和运行环境为准，重点包括 `app.py`、`requirements.txt`、`init_db.py`、`sql/r0703.sql`、`dataset/travel_reviews_30000.csv`。
- 论文格式依据 `2026届毕业论文模板` 目录中的学校模板。

<!-- section: core_workflow -->
# 核心工作流

- 先基于现有论文稿完善正文结构、字数、参考文献、致谢、图表和学校格式细节。
- 再结合系统代码与运行结果，补足论文中的实证分析、系统设计和演示支撑内容。
- 如需继续修改系统，优先使用项目本地 `.venv` 与 Docker 中的 MySQL 环境完成验证。

<!-- section: boundaries -->
# 边界与约束

- 全程以中文作为主要工作语言。
- Python 相关执行优先使用项目本地虚拟环境 `.venv`，避免误用系统级解释器。
- MySQL 使用 Docker 容器 `tourist-mysql`，数据库名为 `r0703`。
- 论文内容需要符合本科毕业论文要求，不写与研究无关的人和事，导师致谢需实事求是。
- 工作区内已有用户文件和已完成修改，不应随意回退或覆盖无关内容。
